一、项目概述（业务视角）

解决什么问题？

在 OPM（运营绩效管理系统）中，业务人员每天需要打开大量 Excel 报表来回答日常问题。本 Skill 提供一个自然语言查询入口，让用户可以直接用“人话”提问，系统自动完成意图理解、报表定位、数据提取与回答生成。

典型支持场景

场景示例说明
我的包干航线的客座率是多少按用户身份自动限定包干航线范围，查找客座率
海口到北京首都未来两天的客座率和票价解析航线、未来时间范围、多指标提取
HU7778 明天的余票解析航班号、日期、指标
未来航班竞航价格差识别竞航/竞争对手分析意图
各航司净利润同比谁表现得最差跨航司同比分析，自动定位经营提升分析报表
单机边际贡献 / 小时边际贡献最高航班经营指标快速查询与排序

二、核心工作流程

  1. 意图解析：规则解析 + 本地 LLM 补槽，输出结构化意图（航线、日期、指标、分析模式）。
  2. 查询规划：根据意图路由到报表族，判定是否需要实时刷新数据。
  3. 数据获取：优先读取本地 Excel 镜像；若缺失/过期/不匹配，则触发 OPM 实时导出。
  4. 结构化提取：从 Excel 中提取表头、行数据，解析出目标指标列。
  5. 数据过滤：按航线、日期、航班号、公司、机型、用户包干范围等条件精确过滤。
  6. 业务分析：针对特定报表执行分析引擎（如竞航分析、同比排名分析）。
  7. 答案渲染：生成面向用户的最终回答文本。
  8. OpenClaw 信封：返回标准化 JSON，供 OpenClaw 统一消费。

3.2 关键技术设计

混合意图解析

规则解析器负责高置信度提取：航班号、航线、相对时间词、指标关键词。
本地 LLM仅在规则不完整时补槽，严禁控制执行流程。
校验器合并结果，并将机场别名映射为标准三字码。

时间语义规范化

将口语化时间统一转换为标准结构：

  • 明天 → single_date
  • 未来两天 → relative_future_range
  • 近三天 → relative_past_range
  • 4月1日到4月3日 → explicit_range

报表路由与本地预检

根据意图路由到报表族。对高价值报表定义 Schema 契约，在读取 Excel 前先做预检：检查文件存在性、结构满足度、航线/日期匹配度。预检失败即触发实时刷新。

本地优先 + 实时兜底

优先使用 opm_mirror 本地 Excel；当文件缺失、过期（默认 >1小时）、不匹配未来日期时，自动调用 PowerShell/Node 脚本从 OPM 在线系统导出并回写本地。

3.3 OpenClaw 集成合约

唯一入口：

python scripts/runner.py "<query>" --user <user> --output-format json

输出标准化 JSON 信封，关键字段包括：

字段说明
ok是否成功
stage失败阶段（intent / planning / execution）
reason_code机器可读错误码
intent解析后的结构化意图
plan查询计划（报表族、刷新策略、分析引擎）
source_meta数据源元信息（本地文件 / 实时导出）
analysis_result分析结果摘要
answer_text最终面向用户的回答文本
message / next_action失败时的提示与下一步建议

五、设计原则与约束

  1. 结构化输出优先：所有中间结果都有机器可读的 JSON Schema，不直接丢原始 Excel 给调用方。
  2. 编排必须确定性：runner.py 的调用链是固定的，不允许 LLM 决定执行流程。
  3. LLM 仅辅助解析：本地小模型只能做 slot filling，不能选报表、不能读 Excel、不能推断不存在的事实。
  4. 报表特定逻辑模块化：竞航分析、经营提升分析等都有自己的 analysis/*.py 模块。
  5. 失败原因机器可读：统一使用 reason_code（如 route_not_found_in_report、live_refresh_failed）。
  6. 避免过度特化：新增能力必须抽象为可复用的语义槽或枚举，不允许为某个特定短语写死逻辑。

六、运维与使用方式

构建报表目录

首次使用或新增报表后，需要重建 catalog：

python scripts\build_report_catalog.py

OpenClaw 调用示例

python scripts\runner.py "我的包干航线的客座率是多少" --user zhuanz --output-format json

配置本地意图 LLM（可选）

$env:OPM_NL_INTENT_LLM_COMMAND = "your-local-intent-parser-command"

实时刷新兜底

当本地数据不满足时，Skill 自动调用 export_report_live.ps1。若登录态失效，会引导用户扫码重新登录。

七、评审结论建议

维度评审结论
业务价值 高 将自然语言直接映射到 OPM 报表数据，显著降低业务人员“找报表、看 Excel”的门槛。
架构合理性 合理 “规则为主 + LLM 补槽”避免纯 LLM 不稳定；本地优先 + 实时兜底兼顾速度与准确性。
可维护性 良好 模块职责清晰（intent / planning / data / analysis / render / adapters），新增报表分析只需在对应模块扩展。
测试覆盖 中等偏上 意图解析和核心模块有回归测试，但实时导出和端到端查询尚缺自动化覆盖，建议在 CI 中补充集成测试。
集成规范 明确 OpenClaw 通过单一入口 runner.py 调用，输出标准化 JSON 信封，符合 Skill 合约要求。
