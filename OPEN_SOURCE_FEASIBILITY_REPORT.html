三、作为 OpenClaw Skill 开源的核心分析

结论：可行，但需明确定位

本项目本质是一个"自然语言 → 帆软报表查询"的领域专用框架。架构清晰、分层合理，但业务逻辑深度绑定 OPM 领域。开源后用户无法直接使用，需按模板改造自己的领域配置。

3.2 开源后用户的改造路径

开源后，一个典型的帆软用户要使用此 Skill，需完成以下步骤：

1

替换领域知识

重写 references/*.yaml：synonyms（指标同义词）、column_aliases（列名映射）、report_schemas（报表 Schema）、airport_aliases → 自定义别名

2

重写意图解析规则

修改 intent/parser_rules.py：替换 OPM 专用的指标名、时间短语、航司/航段提取逻辑

3

配置报表路由

修改 planning/router.py：定义自己的报表家族和路由规则

4

编写分析引擎

在 analysis/ 下编写自己的业务分析逻辑

5

配置环境变量

填写 .env，指向自己的帆软服务器和本地镜像目录

6

构建报表目录

运行 build_report_catalog.py 扫描本地 Excel 镜像

3.3 三大核心风险

🔴 风险1
CDP 认证方式不可移植 — 当前依赖"用户手动扫码登录浏览器 → Playwright 复用 Cookie"模式。外部用户无法理解这个流程，且没有标准 FineReport REST API 认证替代方案。
Critical
🔴 风险2
finereport-search 工具链依赖 — excel_index_candidates.py 和 query_opm_nl.py 硬编码引用 C:\Users\ZhuanZ\finereport-search\ 下的外部工具。此工具非公开项目，其他用户无法获取。
Critical
🟠 风险3
领域知识密度过高 — query_opm_nl.py（1600行）内含大量 OPM 特有业务分支（包干航线、前十后十、首航、竞航分析等），难以通过配置剥离。
High

3.4 风险缓解方案

CDP 认证 → 增加 REST API 认证

新增 FR_AUTH_MODE=cdp|api 配置：

  • api 模式：调用 /webroot/decision/login 用 FR_USERNAME+FR_PASSWORD 获取 fine_auth_token
  • cdp 模式：保留现有 Playwright+CDP 方式

预估工作量：2-3天

finereport-search → 可选化 + 内置简化版

方案：

  • 将 finereport-search 依赖改为可选，未安装时降级为仅目录库搜索
  • 内置一个简化版 build_excel_index.py，用 openpyxl 提取单元格文本建 SQLite FTS 索引

预估工作量：1-2天

query_opm_nl.py → 分层拆分

当前 1600 行的巨型文件应拆分：

  • 通用查询执行框架 → core/executor.py
  • OPM 业务分支 → 移入 analysis/ 或标记为 examples/
  • CDP 导出调度 → core/live_export.py

预估工作量：3-5天

login.hnagroup.com → 通用登录检测

将 CAS 登录页检测改为可配置模式：

FR_LOGIN_PATTERNS=\
  login.hnagroup.com|\

# FineReport NL Query Skill

## Prerequisites
- A running FineReport server (or local mirror of exported Excel files)
- Node.js (for CDP-based live export)
- Python 3.10+

## Quick Start
1. Copy `.env.example` → `.env` and configure
2. Customize `references/*.yaml` for your domain
3. Build report catalog: `python scripts/build_report_catalog.py`
4. Query: `python scripts/runner.py "your question" --output-format json`

## Customization Guide
See `examples/opm/` for a complete domain-specific reference.

六、最终建议

推荐策略：分两阶段开源

🟢 Phase A（2-3天）：先做"内部清理版"开源

只做 Phase 0-1 + Phase 5 的部分工作。删除 Hermes、配置化 URL/路径、添加 LICENSE/README。此时项目仍包含 OPM 领域知识，但所有内部敏感信息已移除。定位为 "带业务示例的 Skill 参考实现"。

这样做的好处：快速上线，用户可以看到完整的工作示例（OPM），理解架构如何工作。

🟡 Phase B（1-2周）：做"通用模板版"

完成 Phase 2-4。解耦 finereport-search、实现 REST API 认证、剥离领域知识为示例。定位为 "可定制的通用帆软报表 NL 查询 Skill 模板"。

这样做的好处：用户可以基于模板快速搭建自己的领域查询 Skill。

💡 关键洞察

此项目最有价值的开源资产不是"OPM 报表查询"，而是以下三个可复用的技术组件：

  1. 帆软报表 CDP 自动化导出引擎（export_report_generic_live.mjs）— 支持任意 FineReport .cpt/.frm 报表的参数填充 + Excel 导出
  2. 自然语言意图解析框架（intent/）— 规则引擎 + 可选 LLM slot filler + 校验修复
  3. OpenClaw Skill 契约模式（adapters/openclaw_contract.py）— 结构化信封 + 分阶段状态 + 失败降级

这三个组件即使不作为完整 Skill，也可以独立被其他开发者复用。
