一、当前已完成功能

  • 自然语言解析：支持时间、日期区间、月度、近三天、上周、航班号、航段、时刻、航司、机型、前十/后十、首航、同比、最好/最差、异常/改进等语义。
  • 报表候选召回与排序：通过本地报表目录、SQLite 索引、别名映射、画像加权，找到最可能命中的报表。
  • 本地 Excel 取数：对普通报表直接抽取结构化行列并做过滤、聚合、top1/topN 返回。
  • 实时导出兜底：本地表不准、过期或空表时，自动走 OPM 实时导出。
  • 复杂 .frm 组合报表支持：可从加载过程里发现内部 .cpt 组件，按指标关键词挑组件，再直连抓取该组件表格数据。
  • 组件批量入库：支持“发现组件 -> 导出 Excel -> 增量写入 SQLite”，为后续高召回低时延做准备。
  • 竞争态势分析：针对“票价/客座率与竞航相比有没有异常或改进空间”已能产出简要业务建议。
  • 针对非标准参数面板的 DOM 级控件回填：已在 航空集团前十后十航班 这类报表落地，修复默认日期误导出的问题。
  • 快速路径优化：对“航空集团上周小时边贡最高的航班”“航空集团上周总边贡最高的航班”这类固定命中问题，已直接进入目标报表实时导出和 top1 读取。
  • 新鲜度策略：本地索引库或本地报表文件只要超过 1 小时未更新，即使本地能命中，也会强制走线上实时查询。

三、当前架构

1. 查询主流程

  1. 用户输入自然语言问题。
  2. parse_query_intent.py 解析指标、时间、实体、筛选条件、比较口径、返回形态。
  3. query_opm_nl.py 从报表目录和 SQLite 索引中排序候选报表，并结合画像做 rerank。
  4. 优先读本地镜像 Excel；若缺失、过期、空表或过滤后无结果，则走实时导出。
  5. 若是复杂 .frm 报表，则优先尝试组件导出；必要时自动发现全部 .cpt 组件并按指标择优抓取。
  6. 抽取表格结构后做过滤、排序、极值、同比分析、竞航分析，最后输出答案。

2. 关键脚本

脚本 作用
scripts/query_opm_nl.py 总入口，负责召回、导出、取数、答案组织

scripts/export_report_generic_live.mjs 通用 OPM 实时导出，现已支持部分 DOM 级参数回填

scripts/export_components_and_index.py 组件批量导出并入 SQLite 索引

四、当前已明确的优化点

  • 通用控件映射还不够，部分 FineReport 页面不是标准 widget，需要补 DOM 级控件识别和回填。
  • 复杂 .frm 报表虽然能发现组件，但“组件关键词 -> 组件选择”的画像还可以更细，减少试错和等待。
  • 部分问法仍依赖实时导出，主链路时延偏高，适合继续扩充离线组件索引。
  • 目前对个别报表做了定制 fallback，后续应抽象成“参数面板结构识别器”，避免一张报表写一段逻辑。
  • 少数全链路回归在 query_opm_nl.py 层仍有超时风险，需要继续清理不必要的重试和多轮刷新。

六、结论

当前方案已经具备“通用自然语言问报表”的主体能力，尤其是复杂报表组件发现、组件批量入库、组件直连抓表、自然语言过滤和业务分析这几块已经形成闭环。下一阶段重点不是再补单点特化，而是把控件识别、组件画像和超时治理继续抽象成更通用、更稳定的基础设施。
